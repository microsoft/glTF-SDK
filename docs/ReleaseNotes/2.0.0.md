# glTF-SDK 2.0.0 release notes

## Breaking release

2.0.0 is intentionally source- and ABI-incompatible with 1.9.5 where JSON
vendor types crossed the SDK boundary.

Removed:

- `GLTFSDK/RapidJsonUtils.h`;
- `ExtrasDocument::GetDocument()` and the public vendor DOM;
- `ValidateDocumentAgainstSchema(const rapidjson::Document&, ...)`; and
- installed/transitive RapidJSON headers and build targets.

Replacements:

- `ExtrasDocument::ToJson()` returns deterministic compact JSON;
- `ExtrasDocument::HasMember()` replaces direct DOM member checks;
- existing typed root/member/JSON Pointer extras operations remain available;
- schema validation accepts serialized document JSON; and
- extension handlers continue to exchange serialized JSON strings.

## JSON parsing and validation

- nlohmann/json 3.12.0 `ordered_json` is the single production DOM.
- Valijson 1.0.6 is forced to Draft-04 and carries repository patches for the
  ordered adapter, RFC-aware references/cycles, structured keywords, safe
  C++14 metadata lifetime, and average-linear scalar `uniqueItems` checks.
- String and stream deserialization share one strict byte parser.
- Strict parsing builds the ordered DOM directly through SAX, avoiding the
  callback parser's quadratic parent-container cleanup.
- Duplicate names and malformed UTF-8 are rejected.
- Comments, trailing commas, non-finite spellings, and malformed syntax remain
  invalid.
- The maximum nesting depth is 256 containers, counting the root container.
- UTF-8 BOM input is accepted only with
  `DeserializeFlags::IgnoreByteOrderMark`; compact stream input is fixed.
- Existing `SchemaFlags` values are retained, including the shared `0x80`
  value for accessor sparse and sparse-values schemas.
- Validation diagnostics retain the form
  `Schema violation at <pointer> due to <keyword>`.
- Valid documents use a diagnostics-free validation pass; failures rerun the
  exhaustive results-producing path so public diagnostics remain unchanged.

## Serialization

Compact and four-space-pretty established goldens remain byte-exact. Valid
UTF-8 is emitted without ASCII replacement; invalid UTF-8 and non-finite
programmatic values throw SDK exceptions.

SDK fields backed by unordered collections now serialize in lexical order for
repeatability. A small number of unasserted floating tie spellings can differ
while preserving the exact binary value. See
`docs/release-evidence/replace-rapidjson-nlohmann/serialization-differences.md`.

## Dependencies and packaging

nlohmann/json and Valijson are committed, private, build-only dependencies.
Configuration and build do not download or install either dependency.
Installed SDK headers contain no JSON-vendor names or transitive include
requirements. Required licenses and notices are included with the package.

## Validation evidence

- 33 bundled Draft-04 schemas compile and validate the root graph.
- 329 selected official Draft-04 cases pass, including all selected `ref` and
  `refRemote` cases without skips.
- Windows x64, Win32, and ARM64 package/consumer gates pass locally.
- The complete local Debug suite passes.
- Baseline/candidate benchmark values and accepted deltas are recorded under
  `docs/release-evidence/replace-rapidjson-nlohmann/`.
